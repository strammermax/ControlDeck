# Bijdragen

Voer voor een wijziging de relevante Python-tests, TypeScriptcontrole en frontendbuild uit. Elke bugfix krijgt een regressietest die zonder de fix faalt (zie TESTING.md → Regressietests). CI controleert daarnaast shellscripts en het Docker-runtime-image. Beschrijf wat verandert en hoe het is gecontroleerd.

Documenteer wijzigingen in deze map, bij de codewijziging. Maak onderscheid tussen gerealiseerde functies en toekomstplannen. Werk de changelog bij voor een release.

Hergebruikte code krijgt een geregistreerde broncommit, licentie en auteursvermelding in THIRD-PARTY.md. Beoordeel geschiktheid voor de lichte containerarchitectuur en licentiecompatibiliteit vóór opname. Een visuele referentie betekent niet automatisch dat broncode is overgenomen.

Gebruik fictieve adressen en configuratie. Commit geen tokens, databases, logs, interne topologie of privégegevens. Meld beveiligingsproblemen volgens SECURITY.md.
